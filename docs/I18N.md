# Internacionalização (i18n)

Fase 7 do `PLANO_SUBSTITUIBILIDADE.md`. Exemplo: `examples/gvb/i18n` (`pt-BR`, `en`, `ru`,
`ar`; `cargo run --example gvb_i18n`, ou `-- --arvore` para imprimir o texto avaliado de
cada locale). Os catálogos dos dois exemplos (Rust e Luau) ficam em
`examples/comum/i18n/`. O **painel de referência** (`examples/gvb/painel`, Fase 0) também troca
pt-BR ↔ en, com os catálogos em `examples/gvb/painel/locales/`: é um exemplo de i18n num app com
estado em Luau, onde o script guarda **chaves** (`estado.ok`, `status.carregando`) e o markup as
traduz com `{t(chave)}`, então trocar o idioma não pede nenhum código no script.

## No markup

Chamadas dentro de `{…}`, em qualquer texto ou atributo templado:

```xml
<text>{t("titulo")}</text>
<text>{t("ola", nome=usuario)}</text>        <!-- {nome} dentro da mensagem -->
<text>{t("itens", n=contagem)}</text>        <!-- plural -->
<text>{num(preco, 2)}</text>                 <!-- 1.234,56 (pt-BR) · 1,234.56 (en) -->
<text>{date(quando)}</text>                  <!-- 31/10/2026 (pt-BR) · 10/31/2026 (en) -->
<button text="{t('botao.salvar')}" on_click="salvar" />
```

No `.gvb`, dentro de uma string; use aspas simples por dentro:
`text("{t('titulo')}")`, `button(text = "{t('botao.mais')}", on_click = mais)`.

Os argumentos são `nome=valor`: um nome sem aspas é uma **chave do contexto** (`n=contagem`
lê `contagem`), com aspas ou número é literal (`n=3`, `nome="Ana"`). `t(chave)` sem aspas
usa o *valor* da chave de contexto como chave de tradução.

## A locale ativa é `__locale`

É uma chave do contexto. Escrevê-la troca o idioma **ao vivo**: toda interpolação que chama
`t(…)`/`num(…)`/`date(…)` lê `__locale` pelo mesmo caminho das demais chaves, então entra
no conjunto de dependências da subárvore e ela é reavaliada. Não há reinício.

- Num `Component`: `ctx.set("__locale", "en".into())`.
- Em Luau: `i18n.set_locale("en")` (escolhe a mais próxima: `pt` → `pt-br`).
- Um botão de idioma qualquer é só um `on_click` que escreve essa chave.

Com algum catálogo carregado, o motor semeia, ao definir a tela inicial:
`__locale` = a locale do sistema (`LC_ALL`/`LC_MESSAGES`/`LANG`) se houver catálogo para
ela, senão a padrão; e `__locales` = a lista JSON das disponíveis (para um
`<combo items="__locales">`). Um app que já escreveu `__locale` (preferência restaurada)
vence.

## Catálogos

Um JSON por locale. Valor string = mensagem; objeto cujas chaves são **todas** categorias
de plural (`zero`, `one`, `two`, `few`, `many`, `other`) = plural; qualquer outro objeto
agrupa (`{"menu": {"abrir": "Abrir"}}` é `menu.abrir`).

```json
{
  "titulo": "Painel de serviços",
  "ola": "Olá, {nome}!",
  "itens": { "one": "{n} serviço ativo", "other": "{n} serviços ativos" },
  "menu": { "abrir": "Abrir" }
}
```

Carregar:

```rust
GlacierDaemon::new()
    .locales_dir("locales")                                  // pt-BR.json, en.json…
    .locale_json("es", include_str!("../locales/es.json"))   // embutido (serve na web)
    .default_locale("pt-BR")                                 // padrão: o primeiro carregado
```

Em Luau: `i18n.load("es", json_text)`, `i18n.available()`, `i18n.locale()`,
`i18n.t("itens", { n = 3 })`, `i18n.num(1234.5, 2)`, `i18n.date("2026-10-31")`.

**Resolução:** `pt-BR` → `pt` → a locale padrão → a própria chave. Uma chave ausente
**aparece no texto** (a chave) e é avisada no stderr (`[glacier i18n] chave … não existe`):
nunca some em silêncio. Idem `t("plural")` sem `n=`.

## Plural

A categoria sai das regras do CLDR para os idiomas abaixo; os demais usam a do inglês
(`one` só para 1).

| Idiomas | Regra |
|---|---|
| `ja` `zh` `ko` `vi` `th` `id` `ms` | só `other` |
| `pt` `fr` | `one` para 0 e 1 |
| `ru` `uk` `be` | `one` (1, 21, 31…, menos 11), `few` (2–4, menos 12–14), `many` |
| `pl` | `one` (1), `few` (2–4, menos 12–14), `many` |
| `ar` | `zero`, `one`, `two`, `few` (3–10), `many` (11–99), `other` |
| `en` `de` `es` `it` `nl` `sv`… | `one` (1), `other` |

Ausente a categoria pedida, usa-se `other`. O `{n}` da mensagem sai formatado pela locale
(`1.234` em pt, `1,234` em en).

## Número e data

`num(valor, casas)`: separadores por idioma — `1.234,56` (`pt` `es` `it` `de` `nl` `tr`…),
`1 234,56` com espaço fino (`fr`), `1 234,56` com espaço rígido (`ru` `pl` `cs` `sv`…),
`1,234.56` (o resto). `date(valor)`: segundos Unix ou `AAAA-MM-DD`, **em UTC**, no padrão
da locale (`DD/MM/AAAA` pt/es/fr/it, `MM/DD/AAAA` en, `DD.MM.AAAA` de/ru/pl,
`AAAA/MM/DD` ja/zh, `AAAA-MM-DD` ko/sv e o padrão). Valor que não é número/data volta
como veio.

## O que NÃO está feito

- **RTL/bidi.** O `cosmic-text` do `iced` faz o embaralhamento bidirecional **dentro de
  uma linha**: conferido com o exemplo em árabe — as letras se ligam e um trecho latino
  fica no lado certo do árabe. Mas o **layout não espelha**: um título em árabe continua
  alinhado à esquerda, `row` continua esquerda→direita, e `align_x: start/end` não mudam
  com o idioma. Um app árabe/hebraico hoje precisa trocar o alinhamento e a ordem dos
  irmãos por conta própria (por exemplo, uma classe por locale).
- **Dígitos e calendários locais** (٣ em vez de 3, calendário hegiriano): não. `ar` usa
  dígitos ocidentais e separadores do inglês.
- **Hora e fuso:** `date` é só a data, em UTC. Não há `time(…)` nem moeda.
- **Mensagens com gênero/seleção** (`select` do ICU) e **negrito/link dentro de uma
  mensagem**: o catálogo guarda texto puro. Para texto rico traduzido, ponha um
  `<prose>` por locale ou uma chave por trecho.
- **Hot-reload dos JSON de catálogo:** o catálogo é lido na partida.
- **Web (wasm):** `locales_dir` não existe; use `locale_json(include_str!(…))`.
